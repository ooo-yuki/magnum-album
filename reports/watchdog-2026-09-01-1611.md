### 1) `server.ts:2273` — `magnum_ai_usage` ledger падает на анонимах (P0, введён текущим патчем)

```ts
// server.ts:2259-2273 — aiUser может быть null (анонимный текст-бот 8/мин разрешён)
let aiUser: { id: number; username: string } | null = null;
if (rawToken) { try { aiUser = await getUserByToken(rawToken); } catch {} }
if (imageDataUrl && !aiUser) return 401; // image требует auth — OK
// ...
await sql`INSERT INTO magnum_ai_usage (user_id, ip, has_image, model, tokens_requested)
  VALUES (${aiUser.id}, ${ip}, ${imageDataUrl ? true : false}, ${MIMO_MODEL}, 400)`; // ← BUG: aiUser.null!
```

Анонимный `POST /magnum/api/ai` с `{text:"привет"}` без `Authorization` — легальный путь (rateLimit `ai:${ip}` 8/мин, строка 2236). `aiUser` остаётся `null`, но `INSERT` дереференсит `aiUser.id` → `TypeError: Cannot read properties of null (reading 'id')`. `catch` на 2274 проглатывает ошибку (`if !msg.includes("magnum_ai_usage")`), поэтому в клиенте запрос всё равно уходит к MIMO и вернёт `200 {text}`, но каждый анонимный вызов логирует `[ai ledger] failed TypeError` и теряет строку аудита. Миграция `0017_ai_guard.sql:2` объявляет `user_id integer REFERENCES magnum_users(id) ON DELETE SET NULL` — `NULL` разрешён, должен быть `aiUser?.id ?? null`. До патча была попытка `aiUser ? aiUser.id : null` в git diff stash, но в текущем `server.ts:2273` регрессия. Проверка: `curl -s -X POST http://127.0.0.1:3000/magnum/api/ai -H 'Content-Type: application/json' -d '{"text":"ping"}'` — в `journalctl -u magnum-bun` появится `TypeError`.

### 2) `src/pages/ShopPage.tsx:114` — `isValidBundleId` принимает 1-символьные ID, вопреки спеке 2-40 (P1)

```ts
// ShopPage.tsx:114 — текущее
export function isValidBundleId(v:string):boolean{ const s=v.trim(); return !!s && s.length<=40 && /^[a-z0-9-]+$/.test(s); }
// было: /^[a-z0-9-]{2,40}$/  (2..40, без trim)
// стало: 1..40 + trim  — len 1 проходит, факт в FAQ строке 138 остался "isValidBundleId 2-40"
```

`!!s && s.length<=40` эквивалентно `1 ≤ len ≤ 40`. `node -e "…isValidBundleId('a')"` → `true`, а `isValidCosmeticId('a')` (строка 113, `/^[a-z0-9-]{2,64}$/`) → `false` — рассинхрон валидаторов. Последствия: `POST /magnum/api/shop/bundle/buy` пропустит `bundleId:"a"` или `" -"` (после trim `" -"` → `"-"` тоже `true`), создаст запись в `magnum_shop_bundles` с вырожденным ключом, сломает `SHOP_BUNDLES` маппинг (дубли, коллизии с будущими bundle). Фикс: `s.length>=2 && s.length<=40` (или вернуть ` /^\[a-z0-9-\]{2,40}$/.test(s)` после trim, как в `drizzle/schema.ts` CHECK).
