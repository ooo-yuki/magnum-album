## Замечания (3 конкретных, файл:строка)

### 1) `src/pages/GalleryPage.tsx:181-210+ (ARCHIVE_42 210 записей)` — архивные `src` указывают в никуда, SPA маскирует 404
210 записей вида `src: "/magnum/images/gallery-42/archive-СССР-001.jpg"` ... `archive-мемфис-210.jpg` не имеют файлов в `public/images/gallery-42/` (там только 8 файлов: `ls` 12M). Из-за `Caddyfile:8` `try_files {path} /index.html` запрос на несуществующий jpg возвращает `200 text/html; charset=utf-8` (8446 байт index.html, проверено `curl -w "%{content_type}"` + `file HTML document`), а не 404. В браузере `<img src="...archive-*.jpg">` будет битым (broken image) поверх градиента, `onError` не навешан — пользователь увидит иконку сломанной картинки + emoji. Нарушает правило "Галерея только реальные файлы".
**Фикс:** вариант A — сгенерить 210 jpg/webp и положить в `public/images/gallery-42/` (батч через `image_generate`); вариант B — убрать поле `src` у архивных записей и мапить через `REAL_BY_STYLE[style]` (как уже делает `REAL_BY_STYLE` на строке 30-34) — `src: REAL_BY_STYLE[item.style]`; вариант C — добавить `<img onError={(e)=>{e.currentTarget.style.display='none'; e.currentTarget.nextElementSibling?.classList.add('fallback-visible')}}>` и рендерить только gradient+emoji при ошибке. Плюс поправить Caddy: `handle_path /magnum/images/* { file_server }` без `try_files` чтобы отсутствующие ассеты возвращали реальный 404.

### 2) `src/pages/games/MemoryGame.tsx:293` — `localStorage` best захардкожен на `normal`, десинхрон с DIFFICULTY
```ts
const [best, setBest] = useState<number>(() => { try { return Number(localStorage.getItem("memory42-best-normal"))||0; } catch { return 0; } });
```
При `DIFFICULTY = {easy:6, normal:12, hard:18}` (строка ~45) ключ всегда `memory42-best-normal`, а сохранение на строке 495-496 использует динамический `key = \`memory42-best-${diff}\`` — чтение и запись расходятся, рекорд для easy/hard перезатирает normal. Плюс инициализатор читает `localStorage` без `typeof window !== "undefined"` — при гипотетическом SSR/prerender упадёт (хотя сейчас CSR — не критично, но tsc/test окружение без window сломается).
**Фикс:** `const storageKey = \`memory42-best-${diff}\`; const [best,setBest]=useState(()=>{ try{ if(typeof window==="undefined") return 0; return Number(localStorage.getItem(storageKey))||0;}catch{return 0}}); useEffect(()=>{try{localStorage.setItem(storageKey,String(best))}catch{}},[best,storageKey]);` и при смене `diff` перечитывать `best` (dep на `diff`). Сейчас `setBest` не синкает обратно при монтировании — только при победе.

### 3) `server.ts:1286-1293` — promo redeem TOCTOU race без транзакции/атомарности
```ts
if (Number(promo.uses) >= Number(promo.max_uses)) ... // 1289
const ex = await sql`SELECT id FROM magnum_promo_redemptions WHERE user_id=${user.id} AND code=${code} LIMIT 1`; // 1290
await sql`INSERT INTO magnum_promo_redemptions ...` // 1292
await sql`UPDATE magnum_promo_codes SET uses = uses + 1 WHERE code=${code}` // 1293
```
Три последовательных запроса без `BEGIN/COMMIT` и без `FOR UPDATE`. При двух параллельных `POST /promo/redeem` (race) оба пройдут проверку `uses < max_uses` (например 4/5), оба вставят `redemptions`, оба сделают `uses+1` => `6/5` превышение `max_uses`. Аналогично `INSERT` без `ON CONFLICT` — дубль при race второго вставит вторую запись до проверки `ex.length`. `checkRateLimit 12/min` не спасает от конкурентности.
**Фикс:** обернуть в транзакцию `await sql.begin(async (tx)=>{ const r= await tx\`SELECT uses,max_uses FROM magnum_promo_codes WHERE code=${code} FOR UPDATE\`; ... await tx\`INSERT ...\`; const upd= await tx\`UPDATE magnum_promo_codes SET uses=uses+1 WHERE code=${code} AND uses < max_uses RETURNING uses\`` + проверка `upd.length===0 => sold out` }); либо атомарно `UPDATE ... SET uses=uses+1 WHERE code=${code} AND uses < max_uses RETURNING *` и только потом `INSERT` + `409` если `affected===0`. Добавить `UNIQUE(user_id,code)` уже есть — ловить `23505` и отдавать `already redeemed`.
