```ts
  "y2k-01": "/magnum/images/gallery-42/42-memphis-01-800.webp", // 38 — должен быть 42-y2k-01-800.webp (67K, ls 14:16)
  "y2k-02": "/magnum/images/gallery-42/42-memphis-01.jpg",        // 39 — должен быть 42-y2k-01.jpg (2.4M)
  "memphis-01": "/magnum/images/gallery-42/42-memphis-01-800.webp", // 42 — дублирует y2k-01, уже есть мемфис
  "y2k-03": "/magnum/images/gallery-42/42-cyber-01.jpg",           // 43 — кибер вместо y2k

```

`REAL_BY_STYLE` на `:31-34` корректен (`Y2K → 42-y2k-01-800.webp`), но `BASE_ARTS` 7 карточек берёт `REAL_FALLBACK`, поэтому фильтр `Y2K` в UI показывает мемфис-арт, а реальный `42-y2k-01-800.webp` (67K) недоступен. Фикс 4 строки: `y2k-01 → 42-y2k-01-800.webp`, `y2k-02 → 42-y2k-01.jpg`, `y2k-03 → 42-y2k-01-800.webp` (или завести `42-y2k-02` если нужен второй), убрать дубликат `memphis-01`. ### 2. `src/pages/GalleryPage.tsx:181-200` + `public/images/gallery-42/` — 20 archive `archive-*.jpg` soft-200 HTML fallback

`ARCHIVE_42` 20 записей `src: "/magnum/images/gallery-42/archive-СССР-001.jpg"` … `archive-мемфис-020.jpg` — файлов `archive-*` на диске 0 (`ls` только 8 реальных `42-*`). Caddy `try_files {path} /index.html` отдаёт для них `200 text/html` (9439B `index.html`) вместо `404` — в браузере `<img>` битый (хотя `getRealSrc()` маскирует частью стилей, логика цикла 4 картинки скрывает отсутствие уникальных артов). Кириллица в пути (`archive-СССР-`) риск double-encode. Нет `loading="lazy"` и `onError` заглушки. Watchdog `curl -w "%{http_code}"` видит 200 и PASS, но `curl -I | grep content-type` покажет `text/html`. Фикс: `ARCHIVE_42` → циклический маппинг на `REAL_BY_STYLE` (как в watchdog идее 15:56) или `scripts/gen-gallery-archive.ts` (4 источника → 20 webp `cwebp -q 82` modulo), + `onError={e=>e.currentTarget.style.display="none"}` + gradient заглушка, + Caddy `handle /magnum/images/* { root ...; file_server }` без `try_files`.

### 3. `server.ts:1720 + 1752 + 1799 + 1820` + `src/pages/ShopPage.tsx:93` — DDL в хендлерах + рассинхрон валидаторов bundleId

- **DDL в hot path:** `handleChatHistory:1720`, `handleChatSend:1752`, `handleFollowToggle:1799`, `handleFollowsList:1820` каждый делают `CREATE TABLE IF NOT EXISTS magnum_chat_messages / magnum_follows` синхронно внутри запроса. При первом burst (10 req параллельно) — гонка DDL + лишний RTT к Neon (30-80ms). Вынести в миграцию `0016_chat_follows.sql` (уже есть 25 строк) и убрать из хендлеров, оставить только `SELECT/INSERT`.
- **Рассинхрон валидаторов:** `server.ts:727 isValidBundleId(v:unknown)` → `!/^[a-z0-9-]+$/` + `length>40` + `trim()`, а `ShopPage.tsx:93 isValidBundleId(v:string)` → `/^[a-z0-9-]{2,40}$/` (без trim, min 2). Клиент пропустит `" bundle-starter "` как invalid, сервер — как valid после trim; наоборот клиент отклонит `"a"` (1 символ) а сервер пропустит. Унифицировать: вынести `shared/validators.ts` или скопировать точную копию серверной.
- **Follow без индекса:** `handleFollowsList:1822 limit = Math.min(parseInt(limitParam)||20, 50)` ок, но `handleChatHistory:1720 limit OFFSET` без `max 100` + нет индекса `magnum_chat_messages(created_at)` — при 10k сообщений будет seq scan. Добавить `CREATE INDEX ON magnum_chat_messages(created_at DESC)` в `0016`.
