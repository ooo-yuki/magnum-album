## 4) Баг #1 (low, не критично) — `extractToken` принимает токен из query-string `?token=`

**Файл: `server.ts:60-62` `function extractToken`**

```ts
const qp = url.searchParams.get("token");
if (qp) return qp;
```

Токен в URL утекает в access-логи, `Referer`, историю браузера, скриншары/копипасты ссылки. Сам по себе не даёт bypass (без токена всё равно 401), но повышает риск утечки токена. WS-клиенты иногда передают `?token=` потому что `WebSocket` не поддерживает `Authorization`/`Cookie` в браузере — это причина сохранения ветки.

**План фикса (1 дифф, 2 мин):**
```diff
 // server.ts:57 — оставить ?token= только для WS, убрать для HTTP API
 function extractToken(req: Request, allowQueryToken = false): string | null {
   const auth = req.headers.get("authorization");
   if (auth && auth.startsWith("Bearer ")) return auth.slice(7).trim();
-  const qp = new URL(req.url).searchParams.get("token");
-  if (qp) return qp;
+  if (allowQueryToken) {
+    const qp = new URL(req.url).searchParams.get("token");
+    if (qp) return qp;
+  }
   return getCookie(req, "magnum_token");
 }
 // WS: extractToken(req, true)
 // HTTP handlers: extractToken(req) — только Bearer + cookie
```
Альтернатива-минимум: логировать warning если токен пришёл через `?token=` на HTTP (не WS), чтобы отследить клиентов.

Оценка: `presave/click` public — by design, не баг. `GET /magnum/api/coins/add` → 200 HTML SPA-fallback для неизвестного GET (POST корректно 401) — не баг.
