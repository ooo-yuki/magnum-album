## Найденные баги (файл:строка)

### BUG-1 — `server.ts:944-954` — TOCTOU гонка в vault claim без транзакции

```ts
// 944 exists=SELECT ... WHERE user_id= AND vault_id= LIMIT 1
// 946 globalRows=SELECT count(*) ... WHERE vault_id=
// 952 if(globalCount >= limit) return 409
// 953 UPDATE magnum_mining SET balance = balance - price + reward ...
// 954 INSERT INTO magnum_mining_vault (user_id, vault_id) VALUES ...
```

Четыре отдельных SQL без `BEGIN`/`COMMIT`. При двух параллельных `POST /magnum/api/mining/vault/claim` оба пройдут `already claimed` и `sold out` до любого `INSERT`, оба спишут баланс и оба вставят строку. Проверка лимита `globalCount` — stale. Защита только на приложении. Подтверждение: `drizzle/schema.ts:115` таблица `magnum_mining_vault` без `unique(user_id, vault_id)` и без уникального индекса — БД не отклонит дубль.

Риск: двойное списание, превышение `limit` (BELAZ `limit:2` может стать 4), отрицательный баланс при гонке `ensureMiningRow` + `UPDATE`.

### BUG-2 — `public/images/gallery-42/42-y2k-01.jpg:1` (и `42-memphis-01.jpg:1`) — дубликат контента + неверное расширение

- `md5sum`: `42-memphis-01.jpg` и `42-y2k-01.jpg` → один хеш `788871292a778b8b4c2d20645924c911` (2.4 MB каждый). Два разных стиля (memphis vs y2k) показывают одну картинку.
- `file *.jpg` → все четыре `.jpg` на деле `PNG image data, 1536×1024` (не JPEG). Расширение `.jpg` вводит CDN/Caddy `Content-Type` в заблуждение; браузер грузит PNG под видом JPEG.
- Источник: `public/images/gallery-42/` 8 файлов, но уникальных по контенту — 7 (3 webp уникальны, 1 webp пара дублируется по контенту jpg).

## Идея починки (1)

**Vault: атомарный claim + схема.**

1. `drizzle/schema.ts:115` — добавить `unique("magnum_mining_vault_user_vault_unique").on(table.userId, table.vaultId)` (Drizzle `unique()`), `drizzle-kit generate && migrate`. Тогда дубль поймается `catch` как `23505 unique_violation` → `409 already claimed` даже при гонке.
2. `server.ts:handleMiningVaultClaim` — обернуть `SELECT ... FOR UPDATE` + `UPDATE` + `INSERT` в одну транзакцию `await sql.begin(async (tx) => { ... })` (neon serverless `sql.begin`). Внутри: `SELECT balance FROM magnum_mining WHERE user_id= FOR UPDATE`, затем проверки, затем `UPDATE`/`INSERT`. Глобальный `count(*)` заменить на `SELECT count(*) ... FOR SHARE` или проверять лимит через `INSERT ... WHERE (SELECT count(*)) < limit` — чтобы sold-out не переполнялся.
