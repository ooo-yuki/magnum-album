function extractToken(req: Request): string | null {
  const auth = req.headers.get("authorization");
  if (auth && auth.startsWith("Bearer ")) return auth.slice(7).trim();
  const url = new URL(req.url);
  const qp = url.searchParams.get("token");
  if (qp) return qp;
  return getCookie(req, "magnum_token");
}

## 🐛 Найденный баг #1 (единственный, критичный)

**Файл:** `server.ts:1242-1251`
**Строка:** `1242` (`if (url.pathname === "/magnum/api/ws"`) + логика `1245-1250`
**Суть:** WebSocket не требует авторизации. `extractToken` вызывается опционально — если токена нет, создаётся аноним `Братуха_${rand}` и делается `server.upgrade` без проверки. Любой аноним может играть в мультиплеер, обойти `AuthStatus hint` и нагружать комнаты.

**Доказательство:**

```bash
curl -i -N \
  -H "Connection: Upgrade" -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==" -H "Sec-WebSocket-Version: 13" \
  http://127.0.0.1:3000/magnum/api/ws
# → 101 Switching Protocols
# → {"type":"room","you":"Братуха_281","yourId":"..."}
# без Cookie, без Authorization
```

**Почему это баг:** REST-эндпоинты (`/coins`, `/shop/inventory`, `/auth/me`) корректно возвращают `401` без токена, а WS — единственный путь в экономику (`MAGNUM` заявлен как `игры→монетки→магазин→рейтинг`), и он открыт. По фронту написано «Без логина мультиплеер закрыт», по факту — открыт.

## План фикса (без кода, только план)

1. **Запретить анонимный upgrade.** В `server.ts:1242` перед `server.upgrade` добавить обязательную проверку:
   ```
   const token = extractToken(req);
   if (!token) return Response.json({error:"unauthorized"}, {status:401});
   const u = await getUserByToken(token);
   if (!u) return Response.json({error:"unauthorized"}, {status:401});
   // только после этого upgrade с u.username
   ```
2. **Убрать fallback `Братуха_${rand}`** для WS — оставить только `u.username`. Анонимные имена допустимы только если проект сознательно хочет гостевой режим (тогда вынести в `?guest=1` с отдельной логикой, сейчас — несоответствие спекам).
3. **Отдать 401 до upgrade**, а не `101` → затем `{"type":"error"}`. WS-клиент (`src/hooks/useWs` / `src/store/ws.ts`) должен обрабатывать `401` и показывать модалку `AuthStatus` («Войди, братуха»).
4. **Покрыть тестом:** `curl -i -H "Upgrade: websocket" … /magnum/api/ws` без токена → ожидать `401`, с валидным `magnum_token` → `101`. Добавить в `reports/` или `tests/e2e/ws-auth.test.ts`.
5. **Проверить регрессии:** `handleMe`, `handleCoinsGet`, `handleShopInventory` уже используют `extractToken` → `401`; WS должен стать консистентен с ними. После фикса перезапустить `Bun.serve` и прогнать этот же чек.
