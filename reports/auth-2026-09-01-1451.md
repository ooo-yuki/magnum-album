## Баг #1 (единственный, но критичный) — WS без авторизации

**Файл:** `server.ts:1639-1651`

```ts
// server.ts:1639-1651 — ТЕКУЩИЙ КОД (уязвим)
if (url.pathname === "/magnum/api/ws" || url.pathname === "/magnum/api/ws/") {
  const username = (url.searchParams.get("username") || url.searchParams.get("name") || "").trim().slice(0, 24) || `Братуха_${Math.floor(Math.random()*900+100)}`;
  let authName: string | null = null;
  const token = extractToken(req);
  if (token) {
    try { const u = await getUserByToken(token); if (u) authName = u.username; } catch {}
  }
  const finalName = authName ?? username;            // ← fallback на анонима
  const ok = server.upgrade(req, { data: { id: crypto.randomUUID(), username: finalName, roomId: null } });
  if (ok) return undefined as unknown as Response;
  return Response.json({ error: "Upgrade failed" }, { status: 426 });
}
```

**Проблема:** токен опционален. Если `extractToken` вернул `null` или `getUserByToken` вернул `null` (протухший токен / нет cookie) — код всё равно делает `server.upgrade` с `Братуха_XXX`. Любой аноним попадает в `room`, может играть, спамить лобби, обходить `AuthStatus` hint. Raw socket без токена:

```
→ GET /magnum/api/ws  Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
← HTTP/1.1 101 Switching Protocols
~ {"type":"room","room":{"id":"room-mtisbowd-ig5k","state":"waiting","players":[{"name":"Братуха_643","score":0}]},"you":"Братуха_643"}
```

**Риск:** обход авторизации в мультиплеере, накрутка онлайна, анонимный флуд. Требование ТЗ: «каждая фича без спеки — баг, без логина мультиплеер закрыт» (`AuthStatus.tsx: hint`).

**План фикса (1 файл, ~5 строк):**

```ts
// server.ts:1639 — фикс: требуем токен строго
if (url.pathname === "/magnum/api/ws" || url.pathname === "/magnum/api/ws/") {
  const token = extractToken(req);
  if (!token) return Response.json({ error: "unauthorized" }, { status: 401 });
  let user: { id:number; username:string } | null = null;
  try { user = await getUserByToken(token); } catch {}
  if (!user) return Response.json({ error: "unauthorized" }, { status: 401 });
  const ok = server.upgrade(req, { data: { id: crypto.randomUUID(), username: user.username, roomId: null, userId: user.id } });
  if (ok) return undefined as unknown as Response;
  return Response.json({ error: "Upgrade failed" }, { status: 426 });
}
```

1. Удалить `url.searchParams.get("username")` fallback — имя только из `getUserByToken`.
2. Если нужен гостевой режим — вынести на отдельный `GET /magnum/api/ws/guest` с rate-limit, а не смешивать с authed каналом.
3. На фронте `src/hooks/useMagnumWS.ts` уже должен слать `credentials: include` — проверить что WS открывается после `refresh()` (сейчас открывает анонимно).
4. Ретест: тот же python raw socket без `Cookie` должен вернуть `401`, с `Cookie: magnum_token=<valid>` — `101`.

**Лог проверки:** `/tmp/auth.log` (3×401 + 426 + `AuthStatus has login` + `extractToken` + WS блок).
