### 2) `src/pages/GalleryPage.tsx:182–532` — 350 `archive-*.jpg` — soft-404 через SPA fallback
`BASE_ARTS` (7 шт) и `MOCK_POOL` (4 шт) теперь правильно маппятся через `REAL_BY_STYLE`/`REAL_FALLBACK` на 6 реальных файлов — отлично. Но архивный пул `arch-СССР-001` … `arch-*-350` всё ещё хардкодит `src: "/magnum/images/gallery-42/archive-*.jpg"` → на диске таких файлов нет, а Caddy/Bun отдают SPA `index.html` с 200 + `text/html`. В итоге `<img>` получает HTML вместо webp и показывает битую картинку, а `curl 200` скрывает ошибку. Фикс: маппить archive через `REAL_BY_STYLE[style]` циклично (4 стиля → 4 реальных webp) или сгенерить 12 превью, + добавить `<img onError={e => (e.currentTarget.style.display='none')}>` и показывать `gradient`+`emoji` как fallback. Также настроить в Caddy `handle /magnum/images/* { file_server }` без `try_files {index.html}` для статики.

### 3) `tests/setup.ts:85–92` — дублированные ключи в `vi.mock("gsap/ScrollTrigger")`
Vite ворнинги `Duplicate key "refresh"` / `Duplicate key "batch"` на каждой прогонке. Причина — копипаст:
```ts
ScrollTrigger: { register, getAll, refresh, batch, create, refresh, batch }
```
дублирует `refresh`/`batch`, верхний-level `getAll/refresh/batch` тоже лишние. Фикс — один чистый мок:
```ts
vi.mock("gsap/ScrollTrigger", () => ({
  default: { register: vi.fn(), getAll: vi.fn(() => []), refresh: vi.fn(), batch: vi.fn(), create: vi.fn() },
  ScrollTrigger: { register: vi.fn(), getAll: vi.fn(() => []), refresh: vi.fn(), batch: vi.fn(), create: vi.fn() },
}));
```
