## 3) Найденный баг — файл:строка и план фикса

### Баг #1 (КРИТИЧНО) — `server.ts:1034` — WS пускает анонимов, обход auth

**Файл:** `server.ts:1034-1045`

```ts
if (url.pathname === "/magnum/api/ws" || url.pathname === "/magnum/api/ws/") {
  const username = (url.searchParams.get("username") || ... ).trim().slice(0, 24) || `Братуха_${Math.floor(Math.random()*900+100)}`;
  // try token for auth name
  let authName: string | null = null;
  const token = extractToken(req);
  if (token) {
    try { const u = await getUserByToken(token); if (u) authName = u.username; } catch {}
  }
  const finalName = authName ?? username;
  const ok = server.upgrade(req, { data: { id: crypto.randomUUID(), username: finalName, roomId: null } });
  if (ok) return undefined as unknown as Response;
  return Response.json({ error: "Upgrade failed" }, { status: 426 });
}
```

**Проблема:** Токен опционален. Если `extractToken` вернул `null` или `getUserByToken` не нашёл пользователя, код **не возвращает 401**, а генерирует `Братуха_XXX` и делает `upgrade`. Любой аноним получает `101` и попадает в дуэль, рейтинг, чат — без регистрации/логина. Даже с `Authorization: Bearer invalid` — тот же `101`.

**Почему не поймал прошлый фикс:** Коммит `55de093` с сообщением `fix(auth): gate multiplayer — WS 401 без токена` не изменил этот блок — `git show 55de093:server.ts` и текущий `server.ts` имеют идентичный WS-блок. Миграция `0004_presave_mining_collect.sql` и другие изменения не затронули auth-gate. Баг пережил «фикс».

**Влияние:** Обход экономики: аноним фармит `coins/mining/duel` без аккаунта, накрутка рейтинга, спам комнат. Нарушение ТЗ: «custom auth без Neon Auth, multiplayer via WebSocket on Bun.serve, no localStorage» + «каждая фича без спеки — баг».

**План фикса (3 шага, 10 строк):**

1. **Закрыть gate в `server.ts:1034`** — требовать валидный токен перед `upgrade`:
   ```ts
   if (url.pathname === "/magnum/api/ws" || url.pathname === "/magnum/api/ws/") {
     const token = extractToken(req);
     if (!token) return Response.json({ error: "unauthorized" }, { status: 401 });
     const user = await getUserByToken(token);
     if (!user) return Response.json({ error: "unauthorized" }, { status: 401 });
     const ok = server.upgrade(req, { data: { id: crypto.randomUUID(), username: user.username, roomId: null } });
     if (ok) return undefined as unknown as Response;
     return Response.json({ error: "Upgrade failed" }, { status: 426 });
   }
   ```
   Убрать fallback `Братуха_XXX` и `url.searchParams.get("username")` — имя берётся только из `user.username`. Если нужен гостевой режим — выделить отдельный `/_guest` эндпоинт с rate-limit.

2. **Починить фронт `src/components/AuthStatus.tsx:19`** — кнопка должна вести на модалку/страницу логина, а не на `/magnum/ideas`:
   ```tsx
   if (!me) return <a href="/magnum/login" className={styles.login}>Вход</a>; // или открыть <AuthModal />
   ```
   Добавить `src/pages/LoginPage.tsx` или `AuthModal` с формами `POST /magnum/api/auth/login|register` + `credentials:"include"` (дизайн из `research.md`).

3. **Починить cron-спеку** — `grep -q "Вход"` → `grep -q "Войти\|Вход"` и проверять WS с полными заголовками:
   ```sh
   curl -s -o /dev/null -w "%{http_code}" -H "Sec-WebSocket-Version: 13" -H "Sec-WebSocket-Key: x3JJHMbDL1EzLkh9GBhXDw==" \
        -H "Connection: Upgrade" -H "Upgrade: websocket" http://127.0.0.1:3000/magnum/api/ws | grep -q "401" \
        && echo "WS gated ✅" || echo "WS OPEN 🔴"
   ```

**Проверка после фикса:**

**Доп баги (не критично, на след. проход):**
- `server.ts: extractToken` берёт `?token=` из query — токен утекает в логи/Cache/Referer. Оставить только `Authorization` + `HttpOnly cookie`.
- AuthStatus ссылка `href="/magnum/ideas"` вводит в заблуждение — идеи доступны и без логина, пользователь не понимает где логиниться.
