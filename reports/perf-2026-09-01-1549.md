## Оптимизация этого тика: Runner sprite 800px webp

**Проблема:** `public/images/5opka-runner.png` — **1.4 MB (1536×1024 RGB)** загружался как `new Image()` в `RunnerGame.tsx:224` без сжатия, без webp, без `decoding=async`/`fetchPriority`. На каждом заходе в `/games/runner` тянулся полный 1.4M PNG, даже на мобильных (где достаточно 800px). Единственный игровой спрайт без 800px-webp оптимизации — все остальные covers/gallery уже имели `-800.webp`.

**Решение (1 файл + 1 патч):**

1. **Конверсия PNG → 800px WebP (Pillow LANCZOS):**
   - `public/images/5opka-runner-800.webp` — **800×533, 34 KB, quality=80** (vs 1406 KB PNG)
   - Экономия **−97.6% (−1372 KB)** на каждом запросе `/games/runner`
   - Создан: `python3 PIL: resize 1536×1024 → 800×533 LANCZOS → WEBP q80`
   - Скопирован в `dist/images/` и `/srv/magnum/images/` (вне очереди `syncPublicAssets`, т.к. создан после `build.ts`)

2. **RunnerGame.tsx — webp-first с PNG fallback + hints:**
   ```ts
   img.fetchPriority = "low";
   img.decoding = "async";
   img.src = "/magnum/images/5opka-runner-800.webp";
   img.onerror = () => { // fallback для старых браузеров без webp
     fb.src = "/magnum/images/5opka-runner.png"; 
   }
   ```
   - `fetchPriority=low` — спрайт не LCP (canvas-игра, below-fold), не конкурирует с tusa-meduza preload
   - `decoding=async` — не блокирует main thread
   - Fallback PNG гарантирует совместимость (Safari <14 edge)

**Эффект:**
- Runner: **−1372 KB (−97.6%)** на каждом cold load `/games/runner`
- LCP/CLS не затронуты (игра ниже фолда, canvas)
- dist +520K за тик — новый hashed build (норма: каждый build +1 main + новые chunks); stale mains 19× — накопленный техдолг, не критичен для /srv/magnum (cp -r перезаписывает, но dist растёт). Следующий тик: добавить stale-cleanup в build.ts (rm старых `main-*.js`/`chunk-*.js` не вошедших в `result.outputs`).
