### BUG-1 — `DAILY_KEY` dead code + отсутствие лимита «одна попытка в день» — `src/pages/games/Game2042.tsx:411` и `469:475`

- **Файл:** `src/pages/games/Game2042.tsx:411` `const DAILY_KEY = "2042-daily"; void DAILY_KEY;` + `src/pages/games/Game2042.tsx:462-475` (`startDaily`/`restart`)
  ```ts
  // 411
  const DAILY_KEY = "2042-daily"; void DAILY_KEY; // подавление unused, но ключ нигде не читается/пишется
  // 462
  const startDaily = useCallback(() => {
    setGrid(seededBoard(dailySeed()));
    setDailyMode(true); ... setSubmitted(false); // нет проверки localStorage/Neon, нет записи DAILY_KEY
  }, []);
  // 469
  const restart = useCallback(() => {
    if (dailyMode) { setGrid(seededBoard(dailySeed()+moves+score)); } // seed+moves+score ломает детерминизм daily
  }, [dailyMode, moves, score]);
  ```
- **Почему баг:** UI обещает «ЕЖЕДНЕВНЫЙ ЧЕЛЛЕНДЖ — одна попытка в день — топ попадёт в рейтинг MAGNUM» (`:541`), но `DAILY_KEY` нигде не `getItem/setItem` и не уходит в `magnum_daily_claims`/`magnum_game_scores`. Игрок может жать «Ежедневный челлендж» бесконечно, спамить `POST /magnum/api/games/submit` и накрутить рейтинг. `restart()` в daily-режиме ещё и делает `dailySeed()+moves+score` — каждый рестарт новая доска, теряется смысл «единой доски дня» (seed должен быть только `dailySeed()`). `void DAILY_KEY` — типичный lint-хак, скрывающий неиспользуемую переменную.
- **Риск:** P1 — экономика/рейтинг: накрутка daily + несоответствие спеке «1 попытка/день».

### BUG-2 — `historyRef.current.length` в JSX не триггерит ре-рендер — `src/pages/games/Game2042.tsx:636`

- **Файл:** `src/pages/games/Game2042.tsx:277` + `:636`
  ```ts
  // 277
  const historyRef = useRef<Array<{grid:Grid;score:number;moves:number}>>([]);
  // 636
  <button onClick={undo} disabled={historyRef.current.length === 0}>Отменить ({historyRef.current.length}/6)</button>
  ```
  `doMove` пушит в `historyRef.current` (`:313-314`), но `historyRef` — mutable ref, React не ре-рендерит при его изменении. Счётчик `(0/6)` и `disabled` обновятся только когда сработает другой `setState` (`setGrid`/`setScore`/`setMoves`), а если ход не привёл к `setGrid` (bump) — UI останется на `0/6` и кнопка disabled, хотя undo доступен. Обратное тоже: после `undo()` `pop()` не вызовет ре-рендер. Нужен `useState` для длины или `forceUpdate`/`useReducer`.
- **Риск:** P2 — UX-баг: игрок видит «Отменить (0/6)» и disabled, хотя ходы были; ревьюер может счесть фичу сломанной.
