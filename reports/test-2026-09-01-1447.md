## 5. 3 идеи для новых тестов

1. **promo TOCTOU race** — redeem должен быть атомарен (`SELECT … FOR UPDATE` или `UPDATE … WHERE uses < max_uses RETURNING`). Сейчас `SELECT` → `INSERT` → `UPDATE uses+1` — два параллельных redeem могут пройти `uses < max` одновременно и переполнить `max_uses`. Тест: мок `sql` с задержкой, 10 параллельных redeem одного кода max_uses=1 → только 1 успех, 9 — `sold out`/`already voted`. Требует транзакцию в server.ts.
2. **presaveTracker реального клика** — jsdom тест: рендер Layout с `usePresaveTracker`, клик по `<a href="https://music.thefence.me/psmagnum">` должен вызвать `fetch("/magnum/api/presave/click", POST {url, ts})`, клик по обычной ссылке — не вызывать. Сейчас `presaveTracker.ts` lines 3-11 — 10% coverage, реальный клик не тестируется.
3. **transfer double-spend / отрицательный баланс** — `handleCoinsTransfer` делает `SELECT balance` → `UPDATE balance - amount` без транзакции и без `CHECK balance >=0`. Тест: два параллельных `transfer 800` при балансе 1000 → один должен вернуть 402, иначе баланс уйдёт в минус. Также проверить `amount=0` и `amount=-5` уже покрыто для `coinsAdd`, для transfer — нет.
